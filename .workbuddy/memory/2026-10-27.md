# 2026-10-27 增量二：构建成功/失败通知（software-wocnb-buildnotify 团队，QA 放行 144 例全绿）

## 方案边界（重要，后续别走弯路）

- **CNB 无推送通道**：Swagger 199 端点无 SSE / Webhook 接收 / 长轮询，构建状态只能客户端拉取
- CNB 的 Webhook 是"推到你的服务器"（HMAC-SHA256 签名），桌面端收不了入站请求 → 若将来要做"应用未运行也能收"，必须部署公网中转服务（本轮用户明确选择不做）
- 最终实现：**轮询 + 快照差分**。只拉 `status=pending` 的构建（`pending` 就是运行中，**没有 running 这个值**，枚举为 `pending/success/error/cancel`），从 pending 消失 = 已结束，再按 sn 回查终态

## 实现落点

- `src/composables/useCnbBuildWatch.ts`（约 1100 行）：纯函数 `diffBuildSnapshot` / `summarizeNotifications` / `shouldNotifyStatus` / `isMissingScopeError` + 副作用 `initBuildWatcher`
- Tauri：`tauri-plugin-notification` + `notification:default` + `tauri.conf.json` 的 `"backgroundThrottling": "disabled"`
- 面板：`NotificationsSlideover.vue` 构建结果分区；`pages/index.vue` 铃铛徽标动态；`settings/index.vue` 构建通知卡
- 测试：`src/composables/__tests__/useCnbBuildWatch*.test.ts` 等，全仓 144 例

## 关键踩坑（后续必读）

1. **`backgroundThrottling` 必须写字符串 `"disabled"`**，Tauri 2 的 `BackgroundThrottlingPolicy` 是 `disabled|suspend|throttle` 枚举，**没有 boolean 分支**，写 `false` 会让 cargo build 配置校验直接失败
2. **403 有两个来源**：真缺 scope（errmsg 可解析出 `repo-cnb-history:r`）与 CNB 网关风控（本项目已知，正是自建 native-tls 通道的原因）。**只有能解析出 scope 名时才可永久跳过仓库**，否则一次风控抖动就把该仓库整会话静音
3. **快照必须记录所属组织**（`cnb-build-snapshot-group`）：`selectedGroup` 不持久化，换组织启动会把上一组织的 pending 全判成"已结束"而误报
4. **被跳过/失败仓库的上一轮快照必须并回 next**（`skippedRepos` + `failedRepos` 同等对待），否则下一轮会把其 pending 凭空判成"已结束" → 假警报。红线：**宁可漏报，不能误报**
5. 回查失败（状态未知）只进面板、**不发系统通知**；合并摘要分支同样要有 `knownCount > 0` 守卫
6. macOS App Nap 属进程级降权，应用侧无法强制；靠 `visibilitychange` 补跑 + 快照持久化补推兜底，极端省电场景可能延迟

## 修复：Builds 页签点击后卡住（2026-10-27 晚）

**根因**：`RepoBuildList.vue` 的状态下拉 items 里有 `value: ''`（"全部状态"）。Nuxt UI 的 USelect 底层是 Reka UI，其 SelectItem **禁止空字符串 value**（空串被保留给"未选中/placeholder"语义），渲染期直接抛
`A <SelectItem /> must have a value prop that is not an empty string`。
该异常发生在 Tabs 内容的 watcher 渲染阶段 → 整个页签内容渲染中断 → 用户侧表现为"点击 Builds 后页面卡住/空白"，且生产包没有任何控制台痕迹。

**修法**：
- `RepoBuildList.vue`：引入哨兵 `STATUS_ALL = 'all'`，下拉 value 一律非空；`onStatusChange` 把哨兵还原为 `''`（`setState('')` 删除 state 参数），请求时哨兵不参与（不传 status）。
- `NewIssueModal.vue`：同款隐患（`:items="['', ...priorityOptions]"`）一并修掉 —— 新增哨兵 `PRIORITY_NONE = 'none'` + `priorityItems`，提交时哨兵 → `undefined`；三语新增 `issues.priorityNone`。
- `main.ts`：新增 `app.config.errorHandler`，把渲染/watcher 未捕获异常打到 console.error（此前这类错误在控制台只剩 Vue warn，生产包完全无声，极难排查）。

**排查手法（可复用）**：`pnpm dev` + puppeteer-core 驱动本机 Chrome，`evaluateOnNewDocument` 注入假 `cnb-token`/`cnb-user` 并打桩 `window.fetch` 返回假 CNB JSON，即可在浏览器里复现 Tauri 内的渲染问题（脚本在 /tmp/wocnb-repro）。

**验证**：typecheck / lint / 144 单测 / build 全绿；浏览器实测 Builds 列表 3 条正常渲染、状态筛选写回 `?tab=builds&state=error` 且请求带 `status=error`、`?tab=builds&sn=101` 详情 pipeline→stage 正常、新建 Issue 弹窗优先级下拉可用，全程零 pageerror。
