## 5. GitHub 发版流水线 release.yml（同日完成，三轮 dry-run 实测）

- 新增 `.github/workflows/release.yml`：push `v*` tag = 完整发版（版本校验 → 门禁 → 四平台打包 → GitHub Release）；workflow_dispatch = 打包验证 dry-run（只出 Artifact 不建 Release）。
- 门禁复用：ci.yml 加了 `workflow_call` 触发，release.yml 的 gates job 直接 `uses: ./.github/workflows/ci.yml` —— 门禁步骤只维护一份。
- 构建矩阵（fail-fast=false）：macos-latest 原生 arm64（app+dmg）、macos-latest 交叉编译 x86_64-apple-darwin（GitHub 已退役 macos-13）、windows-latest、ubuntu-22.04（deb+appimage）；tauri.conf.json 的 `targets: "app"` 用 `--bundles` 按平台覆盖。
- **关键坑 1（tauri-action @v0 ≠ dev 分支）**：部署版只在 `includeRelease=true` 时才执行 buildProject（dev 是无条件构建）。dry-run 传 includeRelease=false 会**根本不构建**，且占位 tagName 会让空产物抛 "No artifacts were found"。正确做法：includeRelease 恒 true，dry-run 与发版的区别由 tagName 是否为空承担。
- **关键坑 2（WiX MSI）**：MSI 硬性要求预发布标识纯数字 ≤65535，`-rc.N` 必拒（与 CNB 流水线结论一致）。Windows 打包目标改为按版本动态解析写入 GITHUB_ENV（预发布→仅 nsis；正式版→nsis+msi）。注意 GitHub runner 上 makensis **可用**（CNB 容器不可用），所以 GitHub 的 rc 版能出 NSIS 安装包，CNB 只能出 portable exe。
- macOS 无证书：`signingIdentity: "-"` adhoc，产物可用未公证。
- 实测结果（run 43393503264，dispatch dry-run）：7/7 job success；4 个 Artifact（bundles-{windows,linux,macos-arm64,macos-x64}）；Windows Artifact 实际下载核验只含 `WOCNB_0.1.0-rc.23_x64-setup.exe`；**未创建任何 Release / dry-run tag**（dry-run 语义正确）。
