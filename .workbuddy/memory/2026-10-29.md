# 2026-10-29 工作日志：cnb-cli OAuth 设备授权登录

## 需求与决策（用户拍板四项）
- OAuth 路径：**cnb-cli 设备授权流**（不注册 OAuth 应用、无 ClientSecret）
- CLI 来源：检测系统已装 → 缺失则从官方 Release 下载原生二进制到应用数据目录
- 集成程度：CLI 仅负责登录与令牌生命周期，API 请求仍走 cnbFetch→Rust 通道
- PAT 手动登录保留为次级方式

## 关键技术事实（实测/逆向 @cnbcool/cnb-cli 1.18.3）
- `cnb login` = OAuth2 设备流：`POST /oauth2/device/auth`（form: client_id=cnb_cli）→ 轮询 `POST /oauth2/token`（grant_type=device_code；authorization_pending/slow_down+5s/access_denied/expired_token）
- **CLI 会自己打开浏览器**（tryOpenBrowser，无环境变量开关）→ 前端不能自动 openUrl，否则双开标签页
- 令牌存 `~/.cnb/token`（0600）：`{auths:{host:{access_token, refresh_token, expires_at(Unix秒), platform_url, client_id, login_host}}}`，兼容旧扁平格式
- 刷新：`POST /oauth2/token`（grant_type=refresh_token&refresh_token&client_id，**无 Basic 认证**——与授权码流文档不同）；CLI 刷新后自动写回
- 原生二进制 URL：`https://cnb.cool/cnb/skills/cnb-skill/-/releases/latest/download/cnb-{darwin|linux|windows}-{x64|arm64}(.exe)`
- `cnb logout --host <host>` 只删单 host；不带 --host 会 unlink 整个文件

## 踩坑与教训
1. **实测 `cnb login` 会真实发起设备授权**：进程即使 8 秒后 kill，用户侧浏览器完成授权后 CLI 仍会写入新令牌——本机 `~/.cnb/token` 被覆盖过一次。教训：涉及真实授权的 CLI 命令禁止在用户机器上做 live 测试，只读源码与令牌文件（脱敏）

## 修复：OAuth 授权登录报「未能从 cnb login 输出中解析授权链接，原始输出为空」

**根因**：`src-tauri/src/cnb_cli.rs` 用 `BufRead::read_to_string` 读 `cnb login` 的 stdout——该 API 阻塞到子进程 EOF（退出）才返回，故 CLI 存活期间共享缓冲区恒为空，100ms×100 轮轮询必然空转到 10s 后判失败。
之前未被发现是因为工程师实测时 spawn 后 8s kill，kill 触发 EOF 后才读到完整输出，掩盖了问题。

**修法**：
- 新增 `pump_reader` + `Utf8ChunkDecoder`：`BufReader::fill_buf()` 拿到可用字节立即写入缓冲区（不等换行、不等 EOF）；`MAX_CAPTURE_BYTES=64KiB` 只限制 append、**仍无条件 consume 管道**（否则子进程写满管道会死锁）
- `Utf8ChunkDecoder` 保留跨块不完整多字节前缀，中文/emoji 不再切坏
- `cli_login_error_message` 统一错误出口：CLI 路径 + 版本 + 进程状态（已退出 code / 仍在运行 / signal）+ stdout + stderr，空流显示 `<空>`
- `strip_ansi`（CSI/OSC/两字节）防御性剥离（CLI 1.18.3 本身无色码）
- 提前退出秒返回（`try_wait`），10s 无链接再给 5s 追加窗口
- **GUI PATH 隐患**：npm 版 cnb 是 `#!/usr/bin/env node` shim，GUI 应用 PATH 只有 `/usr/bin:/bin:/usr/sbin:/sbin` → `env: node: No such file or directory`(127)。修：`resolved_path_env()` 合并 当前 PATH ∪ 登录 shell PATH ∪ node 运行时探测；`probe_cli` 识别 node shim 且无 node 时明确报错并降级下载原生二进制；`CliDetectResult.reason` 透出到前端

**QA 追加修的四项 P2**：
1. `pump_reader` 把 EINTR 当 EOF → 一次信号打断让 stdout 全丢（症状与原 Bug 不可区分）；改为 `Interrupted => continue` + 连续 100 次上限
2. 成功分支 drop `Child` 不回收 → 每次成功登录留一个 `<defunct>`；新增 `reap_child_in_background`（只 wait 不 kill，避免写坏令牌文件）
3. `printf %s "$PATH"` 把 shell stdout 当 PATH → 混入 rc 文件 echo 噪声且带裸 `.`（PATH 劫持面）；改哨兵包裹 `__CNB_PATH_BEGIN__…__CNB_PATH_END__` + `is_usable_path_entry`（非空且绝对路径）过滤
4. PATH 探测在 async 上下文同步阻塞（最坏 9s）→ `spawn_blocking` 包裹 + 备选 shell 超时降到 1s

**验证**：cargo test **71 passed / 0 ignored**（含假 cnb 脚本端到端：脚本先打印标题→sleep→打印链接，链接在 422ms/子进程仍存活时即解析出）；前端 vitest 169；五道门全绿。全程未 spawn 真实 `cnb login`（防再次覆盖用户 `~/.cnb/token`）。

**教训**：
- 读子进程输出**绝不能用 `read_to_string`**（阻塞到 EOF），必须 `fill_buf`/`read_until` 增量读；达到捕获上限后仍要继续 consume 管道防死锁
- 用"kill 后检查"的方式测流式输出会掩盖阻塞问题——正确做法是**在子进程存活期间**断言已拿到输出
- GUI 应用 spawn CLI 必须自己解析登录 shell 的 PATH，不能依赖继承的 PATH；但要过滤相对项与裸 `.`
